# Inviter Studio 1.2.15

Выпуск по итогам полного аудита 24.10.2026: исправлено поведение квот вторых сообщений, добавлены таймауты на сетевые вызовы Telegram, устранены гонки запуска движков и наведён порядок в данных и сборке. Проект переведён под контроль версий Git (первый коммит — снимок до правок; история изменений теперь воспроизводима).

## Квоты вторых сообщений

- У вторых сообщений появился собственный дневной счётчик `followups_today` с тем же лимитом аккаунта и консервативными ограничениями по возрасту. Раньше исчерпание квоты первых сообщений фактически означало неограниченные вторые — это противоречило журналу тестов и README.
- Квота первых сообщений по-прежнему не блокирует вторые: счётчики раздельные, сбрасываются по своим датам в полночь.
- README и справка F1 приведены к фактическому поведению: остановка задачи и выход отменяют ещё не отправленные вторые сообщения (исход виден в журнале и итоговом счётчике); кнопка отмены остаётся для случаев сбоя завершения.

## Надёжность движков

- Все запросы Telegram в `add_user_to_chat` (поиск участника и чата, проверка прав, само приглашение) получили таймаут 30 секунд; таймаут классифицируется как неизвестный исход без автоматического повтора. Авторизация входа — 30/15 секунд, выгрузка диалогов для прогрева — 120 секунд. Зависший прокси больше не способно заморозить задачу безнадёжно.
- `running` в движках приглашений и рассылки устанавливается синхронно до первого ожидания: два одновременных запуска не могут оба пройти проверку.
- Несоответствие типа кампании теперь видно в журнале и критическом сообщении, а не пропадает молча в future.
- Финализация задач строит итог заранее и вызывает завершающий колбэк всегда, даже если очистка упала: кнопки интерфейса не застревают в заблокированном состоянии.
- Прогрев пробрасывает отмену задачи (раньше проглатывал `CancelledError`), планировщик задач логирует неожиданные сбои future.

## Прогрев

- Действие «Просмотр профиля» стало настоящим: открывается профиль реального участника выбранного чата через `GetFullUser`. Для вещательных каналов без доступных участников честно фиксируется «обновлены данные канала».

## Слой данных

- `update_account` читает и пишет в одной транзакции `BEGIN IMMEDIATE`.
- Удаление аккаунта повторно проверяет занятость сессии перед удалением файлов; при гонке файл остаётся целым.
- Все изменения таблицы вторых сообщений фильтруются по кампании.
- Настройки расписания читаются одним запросом — заметно меньше открытий базы в режиме ожидания ответов.
- Убрана недействующая ветка смены прокси после соединения.
